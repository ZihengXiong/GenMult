# WhatsApp 通道配置

将 Memoh Bot 接入 WhatsApp,等于把它装进你的私人/内部 WhatsApp 客户端,
用日常聊天的方式直接对话。Memoh 通过 whatsmeow 协议库连接,
和 WhatsApp Web 网页版用的是同一套多设备协议,无需重新注册手机号,
也不需要 WhatsApp Business API 的密钥。

> WhatsApp 多设备协议面向个人账号与小型内部群,**严禁用于群发或骚扰**——
> 看起来像 spam 的账号会被 WhatsApp 直接封禁。

## 第一步:添加 WhatsApp 通道

1. 在 Memoh Web UI 的 Bot 详情页打开 **平台 (Platforms)** 标签页。
2. 点击 **添加通道**,选 **WhatsApp**。

## 第二步:扫码登录(默认)

1. 点击 **获取二维码**。Memoh 会创建一个新的 whatsmeow 会话并展示二维码。
2. 在手机上打开 WhatsApp -> **设置 -> 关联设备 -> 关联设备**,
   扫描页面上的二维码。
3. 在手机上确认关联,登录成功后页面会自动刷新并保存凭据。

二维码大约每 20 秒刷新一次,过期后点击 **刷新二维码** 即可。

## 第二步(备选):用电话号码配对

如果网络不稳定,二维码反复过期,可以改用配对码:

1. 先点击 **获取二维码** 启动会话。
2. 在同一面板点击 **改用配对码登录**,输入完整的手机号(带国家代码,
   纯数字,例如 `8613800138000`)。
3. Memoh 会返回一个 8 位的配对码,格式为 `ABCD-EFGH`。
4. 手机端 WhatsApp -> **设置 -> 关联设备 -> 改用电话号码连接**,
   输入这个配对码即可。

## 第三步:配置用户绑定

在通道设置里为每个需要识别的用户填写 **WhatsApp JID**:

- 手机号,例如 `15551234567`,Memoh 会自动归一化为 JID。
- 直接 JID,例如 `15551234567@s.whatsapp.net`。
- 群 JID,例如 `120363000000000000@g.us`,用于绑定到具体的群聊。

## 可选设置

| 字段 | 说明 |
|------|------|
| **出站代理 (Proxy)** | 可选 `http://`、`https://` 或 `socks5://` URL,会同时应用到 WhatsApp websocket 和媒体传输。当你的服务器无法直连 WhatsApp 时启用。 |
| **客户端显示名 (Client Display Name)** | "关联设备" 列表里显示的浏览器名称,例如 `Chrome (Linux)`。WhatsApp 会校验,只接受常见的浏览器/操作系统组合。 |

## 已支持的能力

- **文本消息**——私聊和群聊。
- **群聊**——区分群里不同发言人,并按用户保留独立记忆。
- **回复/引用消息**——入站(机器人能看到你回复了哪条消息)和
  出站(机器人回复时会引用原消息)都支持。
- **入站媒体**——图片、视频、音频、语音、文件、贴图,whatsmeow 自动
  下载并解密,转成 data URL 形式的 attachment 给 bot。
- **出站媒体**——bot 可以发图片、视频、语音、文件等,Memoh 会上传到
  WhatsApp 的 CDN 并发送加密引用。
- **@提及和回复识别**——路由 metadata 里附带 `is_mentioned` 和
  `is_reply_to_bot`,可以在 ACL 里只让群聊机器人响应被 @ 或被回复
  的消息。
- **掉线处理**——当 WhatsApp 注销了会话(在手机上手动移除了关联设备,
  或者别处登录),Memoh 会自动把通道置为禁用。重新走一次扫码/配对
  即可恢复。

## 常见问题

- **二维码反复过期。** 改用配对码,或在通道设置里配上代理。
- **群聊里看不到媒体附件。** 默认上限 64 MiB,超过的不会下载;
  小文件总是能正常解密。
- **群聊机器人太吵。** 加一条 ACL,在群聊里要求 `is_mentioned == true`
  或 `is_reply_to_bot == true` 才回复。
- **报错 `whatsapp session is not logged in`。** 重新扫码登录。
  底层 SQLite 会话文件在 `<data_root>/channels/whatsapp/<bot-id>.db`,
  删掉这个文件即可强制重新关联。
